# Руководство для AI-агентов

## Обзор проекта

Это учебный проект по SQL на русском языке, посвященный базе данных авиалиний. Здесь нет прикладного кода, HTTP-сервиса или исполняемой программы: основной результат — схема MySQL, загрузка исходных CSV-данных и запросы к ним.

Помогай с выполнением заданий, рассказывая общую теорию необходимую для выполнения.
Не присылай полное решение без прямой просьбы пользователя.

Основной источник требований — `Задание_запросы_БД_самолеты.pdf` (12 страниц, 70 заданий). В `task.sql` сейчас есть решения заданий 1–47; задания 48–70 еще не оформлены. Отдельный файл `task_2.sql` содержит хранимую процедуру и функцию. Правильно выполненые задания отмечаются в файле `README.md`.

## Технологический стек и конфигурация

- СУБД и диалект: **MySQL**. Используются `LOAD DATA LOCAL INFILE`, `DELIMITER`, хранимые процедуры и функции MySQL.
- Скрипт запуска: **fish**, с shebang `#!/opt/homebrew/bin/fish`.
- Кодировка базы: `utf8mb4`; сопоставление: `utf8mb4_unicode_ci`. Сравнения и `LIKE` для текстовых столбцов по умолчанию нечувствительны к регистру.
- Исходные данные: CSV с разделителем `;`, необязательным обрамлением полей двойными кавычками, заголовком и окончаниями строк CRLF.
- В проекте нет `pyproject.toml`, `package.json`, `Cargo.toml`, lock-файлов, ORM, миграционного фреймворка, Docker-конфигурации или других манифестов зависимостей.
- Минимальная поддерживаемая версия MySQL не зафиксирована. В текущем окружении установлен локальный MySQL 26.7.0.

## Структура и назначение файлов

- `airlines.sql` — создание базы `airlines`, четырех таблиц и внешних ключей; загрузка всех CSV; первичная очистка данных.
- `start.fish` — полное локальное пересоздание базы: включает `local_infile` глобально, удаляет базу, выполняет `airlines.sql` и открывает интерактивный клиент MySQL.
- `task.sql` — решения заданий 1–47, разделенные комментариями `-- Задание N`.
- `task_2.sql` — процедура `get_all_trips(search_client_id)`, выводящая билеты клиента, функция `get_count_client_trips(search_client_id)`, считающая его рейсы со статусом `Arrived`, и итоговый запрос по всем клиентам.
- `csv/airliners.csv` — 25 самолетов.
- `csv/clients.csv` — 24 клиента.
- `csv/trips.csv` — 100 рейсов.
- `csv/tickets.csv` — 100 билетов.
- `Задание_запросы_БД_самолеты.pdf` — формулировки всех 70 заданий и требуемые столбцы выборок.
- `README.md` — контрольный список наличия решений. Сейчас отмечены только задания 1–45, хотя в `task.sql` также есть 46 и 47; при расхождении проверяйте сам SQL-файл.
- `.gitignore` — игнорирует только `.DS_Store`.

## Схема базы и связи

Все столбцы, кроме первичных ключей, объявлены допускающими `NULL`.

- `clients`: `id VARCHAR(12)` (PK), `name`, `phone`, `age INT`.
- `airliners`: `id INT` (PK), `model_name`, `range INT`, `production_year INT`, `color`, `side_number INT`, `country`.
- `trips`: `id VARCHAR(10)` (PK), `trip_code VARCHAR(8)`, `departure VARCHAR(3)`, `arrival VARCHAR(3)`, `status`, `airliner_id INT` (FK).
  - `trips.airliner_id` ссылается на `airliners.id` через `fk_trips_airliner`.
- `tickets`: `id VARCHAR(12)` (PK), `trip_id VARCHAR(10)`, `service_class`, `price INT`, `client_id VARCHAR(12)`.
  - `tickets.trip_id` ссылается на `trips.id` через `fk_tickets_trip`.
  - `tickets.client_id` ссылается на `clients.id` через `fk_tickets_client`.

Имя `range` нужно экранировать обратными кавычками: `` `range` ``. Связи образуют цепочку `clients → tickets → trips → airliners`; билет может не иметь рейса, поэтому для полного набора билетов важен подходящий тип соединения и корректная обработка `NULL`.

### Особенности загрузки и очистки

- Загрузка требует включенного `LOCAL INFILE` как на сервере, так и в клиенте.
- В `clients` строковое значение `'null'` в телефоне заменяется на SQL `NULL`; к телефонам без начального `+` добавляется этот символ. Пробелы в телефонах только выводятся диагностическим `SELECT`, но не удаляются из сохраненных данных.
- В `tickets` строковое `'null'` в цене преобразуется в SQL `NULL`, а завершающий `\r` удаляется из `client_id`.
- В `airliners` завершающий `\r` удаляется из `country`.
- Значения `NULL`, строка `'null'`, пустые результаты и нечувствительность к регистру существенны для условий заданий; не заменяйте эти случаи «более аккуратной» логикой без сверки с PDF.

## Запуск и пересоздание базы

Штатная команда из корня репозитория:

```fish
./start.fish
```

Скрипт использует `mysql -u root` без пароля и завершается интерактивным сеансом MySQL. Для подключения после инициализации без повторного пересоздания базы:

```bash
mysql --local-infile=1 -u root -D airlines
```

**Внимание:** `./start.fish` выполняет `DROP DATABASE IF EXISTS airlines` и безвозвратно удаляет все локальные изменения в этой базе. Он также выполняет `SET GLOBAL local_infile = 1`, влияя на весь MySQL-сервер, и не возвращает прежнее значение настройки. Не запускайте его для обычной проверки одного запроса.

В `start.fish` и четырех командах `LOAD DATA` в `airlines.sql` зашит абсолютный путь `/Users/gordstep/Documents/database/airplaines`. При другом расположении репозитория пути нужно синхронно изменить. Сам `airlines.sql` не удаляет существующие таблицы, поэтому повторный запуск поверх уже созданной базы не является идемпотентным.

`task_2.sql` при необходимости выполняется целиком после инициализации:

```bash
mysql -u root -D airlines < task_2.sql
```

Сохраняйте блоки `DELIMITER`: они нужны клиенту MySQL для разбора тел процедуры и функции. В файле нет `DROP PROCEDURE`/`DROP FUNCTION` или `CREATE OR REPLACE`, поэтому повторное выполнение при уже существующих объектах завершится ошибкой.

## Соглашения при изменении SQL

- Новые решения добавляйте в `task.sql` в порядке номеров с комментарием `-- Задание N` на русском языке.
- Сверяйтесь с PDF: важны не только строки результата, но и точный набор, порядок указанных атрибутов и имена псевдонимов.
- В существующих решениях ключевые слова SQL преимущественно записаны строчными буквами; имена таблиц и столбцов — на английском, псевдонимы — преимущественно в `snake_case`. Следуйте окружающему стилю, не переформатируя весь файл.
- Сохраняйте явные границы диапазонов (`>`, `>=`, `BETWEEN`), требования `CASE`, `NOT IN`, сортировки и обработку `NULL`, заданные формулировкой.
- Задания 10, 20 и 25 содержат `UPDATE` или `INSERT`, а не только чтение. Повторный запуск всего `task.sql` изменяет данные и может упасть на дублировании первичных ключей. Для проверки отдельного задания выполняйте только нужный фрагмент на свежей копии данных.
- После добавления решения обновляйте соответствующий пункт `README.md`, помня, что галочка означает лишь наличие запроса.

## Проверка и тестирование

Автоматических тестов, эталонных результатов, линтеров, форматтеров, CI и команды `test` в репозитории нет. Сборка и установка зависимостей также не требуются.

Проверка выполняется вручную:

1. Инициализируйте локальную базу штатным скриптом только если удаление текущей `airlines` допустимо.
2. Убедитесь, что исходная загрузка дает 25 строк в `airliners`, 24 в `clients`, 100 в `trips` и 100 в `tickets`.
3. Выполните конкретный запрос в MySQL и сравните столбцы, псевдонимы, фильтрацию, сортировку и значения `NULL` с условием в PDF.
4. Для изменяющих запросов проверяйте как результат `SELECT`, так и побочные изменения; для воспроизводимости начинайте с чистой загрузки.
5. Для `task_2.sql` отдельно проверьте создание процедуры и функции, вызов функции и результат итогового запроса.

Не считайте успешное открытие клиента или отсутствие синтаксической ошибки доказательством правильности решения. Существующие решения не имеют автоматической проверки правильности.

## Безопасность и эксплуатация

- Используйте только доверенные CSV: `LOAD DATA LOCAL INFILE` читает локальные файлы через клиент MySQL.
- Не запускайте разрушающую инициализацию на сервере, где база `airlines` содержит нужные данные. По возможности используйте отдельный локальный сервер и ограниченную учетную запись вместо `root`.
- CSV содержат имена и телефоны клиентов; не добавляйте их в лишние логи или публикуемые результаты. Задание 41 специально требует маскирования телефонов.
- Процесса развертывания и production-окружения нет: проект рассчитан на локальную работу с MySQL и ручное выполнение учебных запросов.
